# consensus_citation — independent citation mechanism for Consensus API results

A self-contained citation engine that ingests **Consensus API** search results,
manages them with the same discipline as this repo's deep-research skill, and
drives an LLM to produce an answer whose every factual claim carries an in-text
`[N]` citation — backed by a deterministically generated bibliography.

It is **independent** of the parent skill (`scripts/`, `schemas/`): it mirrors
the proven algorithms (content-addressable IDs, render-time numbering,
evidence-first persistence) but owns its own records so it can carry academic
fields (`journal_name`, `publisher`, `citation_count`, `takeaway`).

## Design principles (inherited from the parent skill)

- **Content-addressable source IDs** — `source_id = sha256(canonical_locator)[:16]`.
  A Consensus result's DOI becomes `doi:10.xxxx/...`; DOI-less papers get a
  stable `consensus:title:<slug>`. Same paper → same ID → automatic dedup,
  even across different queries and DOI prefix variations.
- **Display numbers are render-time only** — `[1][2][3]` are assigned from
  registration order and never stored, so the numbers fed to the LLM and the
  numbers in the bibliography are always the same set.
- **Evidence-first** — each paper's `takeaway` (AI paraphrase) and `abstract`
  (authors' words) are persisted as evidence rows *before* synthesis.
- **No fabrication** — the LLM only writes prose + `[N]` markers; the
  bibliography is generated by code, and an integrity check flags any `[N]`
  that doesn't map to a real source.

## Consensus field mapping

| Consensus field | Where it goes |
|---|---|
| `title` / `paper_title` | source `title` |
| `doi` | normalized → `canonical_locator` (`doi:…`), source `doi`, `raw_url` |
| `authors` | source `authors` (list) |
| `publish_year` | source `year` |
| `journal_name` | source `journal_name` |
| `publisher` | source `publisher` |
| `citation_count` | source `citation_count` + academic credibility score |
| `takeaway` | evidence row, `evidence_type="paraphrase"`, `locator="takeaway"` |
| `abstract` | evidence row, `evidence_type="direct_quote"`, `locator="abstract"` |

## Files

```
identity.py         hashing, canonical locators, JSONL helpers (mirrors parent skill)
normalize.py        Consensus result dict -> (source, [evidence])  (pure)
credibility.py      citation_count + venue + recency -> 0-100 credibility
store.py            CitationStore: register/dedup, display numbers, digest, bibliography
consensus_client.py FixtureConsensusClient (offline) + ConsensusClient (live HTTP)
prompts.py          system/user prompts (anti-fabrication rules from quality-gates.md)
synthesize.py       Claude (claude-opus-4-8) + deterministic offline fallback
verify.py           check_citation_integrity: [N] markers vs registered sources
demo.py             CLI: query -> retrieve -> manage -> synthesize -> verify -> print
fixtures/           bundled sample Consensus responses (illustrative)
tests/              unittest suite
```

## Run the demo

**Offline** (no credentials — bundled fixtures + deterministic synthesis):

```bash
python consensus_citation/demo.py \
  --query "Do statins reduce cardiovascular mortality?" \
  --fixture consensus_citation/fixtures/query_statins.json --strict
```

Expected: a `[N]`-cited answer, a numbered `## Bibliography`, and (on stderr) an
integrity report with `ok=True`; exit code 0.

**Live** (real Consensus + real Claude):

```bash
pip install anthropic
export ANTHROPIC_API_KEY=...      # enables claude-opus-4-8 synthesis
export CONSENSUS_API_KEY=...      # enables the live retrieval client
# optional, if your tenant differs:
export CONSENSUS_API_BASE_URL=...    # default https://api.consensus.app/v1/search
export CONSENSUS_RESULTS_PATH=...    # JSON key nesting the results array, if any
python consensus_citation/demo.py --query "Do statins reduce cardiovascular mortality?"
```

The synthesis path auto-selects: real Claude when the SDK + key are present,
otherwise the offline synthesizer. The retrieval path auto-selects: the live API
when `CONSENSUS_API_KEY` is set (and no `--fixture` is given), otherwise fixtures.

> **Wiring the real Consensus API:** only the return shape was specified, so
> `ConsensusClient` is configurable. Set `CONSENSUS_API_BASE_URL` and, if results
> are nested, `CONSENSUS_RESULTS_PATH`. The client tolerates a bare list or
> `{results|papers|data|hits: [...]}` responses; subclass `ConsensusClient` if
> your endpoint needs a different request/response contract.

Use `--json` for machine-readable output (answer + bibliography + integrity +
`bibliography_json`), `--offline` to force the deterministic synthesizer, and
`--run-dir DIR` to persist `sources.jsonl` / `evidence.jsonl`.

## Tests

```bash
python -m unittest consensus_citation.tests.test_pipeline -v
```

Covers field mapping, synthetic-locator stability, prefix-insensitive +
cross-query dedup, the numbering↔in-text-marker invariant (end-to-end, offline),
bibliography/marker consistency, and hallucination detection. The live-LLM test
is skipped unless `ANTHROPIC_API_KEY` is set.
